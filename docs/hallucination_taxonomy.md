# 客服回复"幻觉"分类体系

> 版本：v1.0  
> 适用范围：智能客服自动回复场景  
> 评测对象：20 条 system_reply vs. knowledge_base

---

## 一、设计原则

1. **可自动判定优先**：每类都要有可观测的文本特征，避免纯语义判断。
2. **严重程度可量化**：高严重度直接关联"是否对用户造成实质损害"。
3. **与 ground_truth 兼容**：在表达上尽量贴合人工标注的语义，便于对齐验证。
4. **正交不重叠**：分类之间尽量互斥，模糊 case 标注主类型 + 备注。

---

## 二、分类体系（5 大类 + 严重度等级）

### 1. 事实编造（FACT_FABRICATION）— 严重度 🔴 P1

**定义**：回复中出现的具体实体（数字、地址、品牌名、材质、优惠名等）在知识库中**完全找不到**，属于凭空捏造。

**典型特征**：
- 知识库中无相关信息（`无（...接口）`、`无...政策`），回复却给出具体数据
- 知识库给出参数 X，回复编造为 Y（如蓝牙 5.0 → 5.3）
- 知识库无相关条目，回复杜撰了具体细节（地址、品牌关系、优惠）

**示例**：
- h02 蓝牙 5.3（KB: 5.0）
- h05 满300减50优惠（KB: 无此活动）
- h07 退货地址（KB: 系统自动匹配）
- h11 北京/上海/广州/深圳门店（KB: 纯线上）

### 2. 能力越界（CAPABILITY_OVERREACH）— 严重度 🟠 P2

**定义**：客服系统**不具备**某项查询/操作能力，回复却假装已执行或能提供该信息。

**典型特征**：
- 知识库明确"未接入 XX 接口 / 不具备 XX 功能"
- 回复却以"我帮您查了"、"已帮您修改"等口吻给出结论
- 属于"承诺做不到的事"，但本身不杜撰具体数据

**示例**：
- h03 物流查询（未接入接口）
- h10 退款进度（未接入接口）
- h14 订单地址修改（未接入接口）
- h18 工单升级（无此功能）

### 3. 政策偏差（POLICY_DISTORTION）— 严重度 🟡 P2

**定义**：知识库有相关政策描述，回复**部分正确 + 部分错误/夸大**，常见于时效、数量、范围、流程的扭曲。

**典型特征**：
- 知识库明确数值，回复给出不同数值（24小时 → 48小时）
- 知识库说"A 支持、B 不支持"，回复说"A 和 B 都支持"
- 流程细节错误（应去 X 页面 → 写在 Y 备注里）

**示例**：
- h04 电子发票正确 + 纸质发票错误 + 备注指引错误
- h08 发货时间偏差 + 快递公司编造

### 4. 安全误导（SAFETY_MISGUIDANCE）— 严重度 🔴🔴 P0（最高）

**定义**：回复内容**可能直接导致用户健康、安全、财务损失**，即便属于信息遗漏或语气误导，也要单独标出。

**典型特征**：
- 涉及禁忌人群（孕妇、儿童、过敏体质）
- 涉及医疗、金融、安全建议
- 知识库有明确警示，回复完全消除警示

**示例**：
- h13 面膜孕妇可用（KB: 含视黄醇衍生物，建议咨询医生）

### 5. 关键遗漏（CRITICAL_OMISSION）— 严重度 🟡 P3

**定义**：知识库中有明确的、对用户决策重要的信息（用户评价、注意事项、限制条款），回复未提及，导致用户决策依据不完整。

**典型特征**：
- 知识库含"用户反馈 / 注意事项 / 限制"
- 回复给出"标准/通用"答案，未传达 KB 中的差异化信息
- 边界模糊，需结合上下文判定

**示例**：
- h20 鞋码标准（KB: 30% 用户反馈偏大半码）

---

## 三、严重度判定逻辑

| 等级 | 含义 | 检测优先级 |
|---|---|---|
| **P0** | 安全误导，可能造成实质损害 | 立即人工介入 |
| **P1** | 事实编造，核心信息虚假 | 立即人工介入 |
| **P2** | 能力越界 / 政策偏差，承诺不可达 | 高优审核 |
| **P3** | 关键遗漏，决策依据不全 | 一般审核 |

## 四、与 ground_truth 类型映射

| 我的分类 | ground_truth 类型 | 备注 |
|---|---|---|
| 事实编造 | 政策编造 / 参数编造 / 优惠编造 / 信息编造（无 KB 数据）| 我合并为"事实编造"，更聚焦"凭空捏造" |
| 能力越界 | 能力越界 | 一致 |
| 政策偏差 | 政策偏差 | 一致 |
| 安全误导 | 安全误导 | 一致 |
| 关键遗漏 | 信息遗漏 | 一致 |

> 说明：本题 ground_truth 的"政策编造 / 参数编造 / 优惠编造 / 信息编造"在我的体系里合并为**事实编造**一类，因为它们的检测方法完全一致（"KB 中找不到该实体"）。分类粒度的选择是为了**让检测规则更通用**，评估时通过混淆矩阵观察一致性即可。

---

## 五、本分类体系的局限

1. **粒度偏粗**：把 ground_truth 中的 4 类合并为 1 类，分类混淆矩阵会有"事实编造"过度集中其他 3 类的现象。
2. **边界模糊**：h04（政策偏差 vs 事实编造）、h20（信息遗漏 vs 政策偏差）属于边界 case，规则触发顺序决定分类。
3. **依赖知识库完备性**：知识库没说"无"的项，规则无法判定为幻觉（如 h14 改地址，知识库说"未接入接口"是规则能抓住的关键）。
4. **不处理语义矛盾**：仅含数据/事实层；语气、礼貌、引导性话术不在检测范围内。
